# Advanced Backend Engineering & Security Skill (V2.3 ARGON DevilScanner-Hardened Standard)

## 1. Purpose & Non-Negotiable Engineering Rules

This master specification and its 17 modular reference files (`00`–`16`, totaling 18 specification files) define a security-first, technically verifiable TypeScript backend engineering standard. Every pattern, code implementation, and verification test across this library obeys these non-negotiable rules:

1. **Zero Trust for Client-Supplied Claims**: Never treat client-provided tenant IDs, user IDs, roles, boolean flags (`isAdmin`, `dualApprovalConfirmed`, `gatewayOidcVerified`), headers, webhook metadata (`claimedTenantId`), or broker event payloads as proof of authorization.
2. **Explicit Trust Boundaries, Threat Models & Limitations**: Every security control documents its trust boundary, threat model, enforcement location, failure behavior, and operational limitations.
3. **Authenticate, Authorize & Bind Cryptographic MACs Before Establishing Database Context (`DEVIL-01` & `DEVIL-02`)**: In multi-tenant PostgreSQL architectures (`withTenantTransaction` and `withPinnedTenantTransaction`), verify at startup that the DB role has `rolsuper = false` and `rolbypassrls = false` (`verifyDatabaseRoleRlsEnforcement`), require a mandatory `gucHmacSecret` (`>= 32` chars), set only `app.current_user_id` + `app.current_user_mac` (bound to `txid_current()::text`) before querying `tenant_members` (`FOR SHARE OF t, tm`), and populate `app.current_tenant_id` + `app.current_tenant_mac` ONLY AFTER active tenant status, active membership status (`status = 'ACTIVE'`), and required action permission are verified. All PostgreSQL RLS policies enforce `security.verify_active_tenant_context(tenant_id)` / `security.verify_active_user_context(user_id)`.
4. **ReBAC Ownership != Administrative Authority & Intra-Tenant BOLA Defense**: Resource ownership (`owner` of an order, file, or project) grants only explicitly mapped owner actions and NEVER bypasses administrative or financial permission checks (`order:refund`, `ledger:export`, `member:invite`, or marking a BaaS project `'COMPLETED'`). File downloads (`authorizeApprovedFileDownload`) and cache hits (`getOrComputeAuthorizedCachedSingleFlight`) must enforce per-user instance authorization inside the tenant.
5. **Fenced Idempotency, Mandatory ACID Maker-Checker & Commit-Before-Throw State Transitions (`DEVIL-05`, `DEVIL-06`, `DEVIL-10`, `DEVIL-11`)**: Mutating operations and payments enforce leased idempotency keys with `lockOwnerToken`, monotonic `fencingToken`, canonical request payload hash verification (`422` on mismatch), periodic lease renewal, conditional completion, and transition to `UNKNOWN_RECONCILIATION_REQUIRED` on ambiguous provider timeouts. Maker-Checker approvals require a mandatory `runInAcidTransaction` runner, verify live Maker and Checker active membership, commit terminal `'EXPIRED'` / `'REVOKED'` transitions before throwing rejection errors, and enforce conditional versioned balance updates + deferred DB balance-invariant triggers (`verify_journal_balanced_at_commit`).
6. **Confused-Deputy, One-Time Nonce & Strict Schema Defense for MCP Tools (`DEVIL-03` & `DEVIL-04`)**: Every MCP tool (`executeMcpToolWithRuntimeAuthz`) requires a non-empty `allowedArgKeys` schema and rejects non-plain objects, circular references, `NaN`/`Infinity`, and prototype pollution. Mutating MCP tools (`isMutating: true`) unconditionally require a `confirmationSecret` (`>= 32` chars), a valid `userConfirmationToken` bound to `(userId, tenantId, toolName, confirmationNonce, confirmationExpiresAtMs, canonicalArgs)`, and atomic server-side one-time nonce consumption (`consumeConfirmationNonceAtomically`).
7. **Unforgeable Glue-Layer Guardrails & Evidence-Based Verification (`DEVIL-07`–`DEVIL-09`, `DEVIL-16`, `DEVIL-22`)**: Pin tenant transaction clients via an unforgeable module-private `WeakMap` (`wrapAsPinnedTenantClient`, `assertPinnedTenantTransactionClient`, `withPinnedTenantTransaction`), wrap server actions in `createAuthenticatedServerMutation()`, enforce active revocation-safe realtime stream controllers (`createRevocationSafeRealtimeStreamController()`), and never mark checklist items `'VERIFIED_FIXED'` without executable passing test IDs (`parseMarkdownSecurityChecklist`).
