## 3. Cross-Module Attack Scenarios & Attack Simulations

### Simulation 1: Cross-Module Intra-Tenant File Download BOLA & Partial-Read Scanner Bypass (`Mod 02` + `Mod 05` — `DEVIL-14`)
1. **Preconditions**: Victim (`user-ceo`) uploads a confidential payroll PDF (`upload-999`) in `tenant-1`.
2. **Attacker Capability**: (a) A buggy or compromised scanner reads only the first 64 bytes of `verifiedScanStream` and returns `CLEAN` without consuming the stream to EOF; or (b) low-privilege `user-viewer` in `tenant-1` attempts to download `upload-999`.
3. **Vulnerable Component**: `StreamingMultiStorageOrchestrator.streamScanAndPromote` and `authorizeApprovedFileDownload` in `Module 05`.
4. **Remediation**: `streamScanAndPromote` reloads the authoritative upload record from `metadataStore`, verifies `integrityScanGate.isCompletedAndVerified() === true` (proving 100% of bytes were hashed to EOF), requires a genuine `MandatoryCdrSanitizerInstance` (`performsFullFormatReconstruction: true`), and `authorizeApprovedFileDownload` enforces owner/ReBAC authorization (`FILE_DOWNLOAD_DENIED_BOLA`).
5. **Regression Tests**: `TEST-22`–`TEST-25`, `TEST-35`, `TEST-61` (Executed & Passed).

### Simulation 2: Maker-Checker Tampered Payload Rollback Trap (`Mod 14` — `DEVIL-05` & `DEVIL-06`)
1. **Preconditions**: An approval `approval-1` is in `'APPROVED'` state for `$1,000`. Attacker mutates the execution request payload to `$999,000`.
2. **Vulnerable Component**: `executeVerifiedBusinessApprovalAndReservation` in `Module 14`.
3. **Actual Failure Before V2.3 Fix**: Inside `runInAcidTransaction`, the code called `await txStore.markApprovalState({ nextState: 'REVOKED' })` and immediately threw `new Error('APPROVAL_PAYLOAD_TAMPERED_REVOKED')`. Because throwing inside `runInAcidTransaction` rolls back the database transaction, the `'REVOKED'` state update was rolled back, leaving `approval-1` in `'APPROVED'` state!
4. **Remediation**: `approvePendingFinancialOperation` and `executeVerifiedBusinessApprovalAndReservation` now return a structured `COMMITTED_TERMINAL_REJECTION` outcome from the transaction callback so `runInAcidTransaction` **commits** the `'REVOKED'` or `'EXPIRED'` state to the database first, and then throws the rejection error after commit.
5. **Regression Tests**: `TEST-31`, `TEST-36`, `TEST-37`, `TEST-55` (Executed & Passed).

### Simulation 3: Post-Acceptance SMS Commit Failure Triggering Double-Send Failover (`Mod 10` — `DEVIL-18`)
1. **Preconditions**: Primary SMS provider (`Twilio`) accepts an OTP SMS and returns `{ providerMessageSid: 'SM123' }`, charging the tenant and delivering the SMS to the user. Immediately afterward, `store.commitReservation()` encounters a transient database error.
2. **Actual Failure Before V2.3 Fix**: Because `commitReservation()` was inside the same `try` block as `primaryProvider.sendSms()`, the `catch` block caught the DB error, classified it as `SAFE_PRE_SEND_FAILOVER` (or `AMBIGUOUS_POST_WRITE` without `providerMessageSid`), and either failed over to `secondaryProvider` (sending a duplicate SMS) or lost `providerMessageSid`.
3. **Remediation**: `dispatchSmsWithBudgetAndFailover` now isolates `primaryProvider.sendSms()` from `store.commitReservation()`. Once `primaryRes` is returned, any error in `commitReservation()` records `providerMessageSid` via `markReservationAmbiguous` and returns `'AMBIGUOUS_RECONCILIATION_REQUIRED'` without ever calling `secondaryProvider`.
4. **Regression Tests**: `TEST-50`, `TEST-62` (Executed & Passed).

## 5. Architecture, Dependency, Privacy, Deployment & Unresolved Risk Reports

### 5.1 Architecture & Dependency Risk Report
- **Installed Runtime Dependencies (`package.json` Audit)**:
  - Next.js `^15.4.9`, React `^19.2.1`, `@google/genai` `^2.4.0`, `lucide-react` `^0.553.0`.
  - **Supply-Chain Risk**: `firebase-tools` (`^15.0.0`) is listed in `devDependencies` and pulls a large transitive dependency tree. In production builds, run `npm ci --omit=dev --ignore-scripts` and enforce lockfile integrity (`package-lock.json` SHA-512 hashes) so compromised postinstall scripts cannot execute in CI/CD.
- **Node.js Runtime Transport Pitfall**: Node's built-in `fetch()` uses Undici, which ignores `https.Agent`. Any developer who copies `resolveAndPinSafeTarget().httpsAgent` into `fetch(url, { agent })` instead of `executePinnedSafeHttpsRequest()` will bypass DNS pinning. Keep `executePinnedSafeHttpsRequest()` as the sole outbound HTTP wrapper.

### 5.2 Privacy & Data-Integrity Report
- **GDPR / Right-to-Erasure vs. Immutable Financial Ledgers & Audit Chains**:
  - Modules 01 and 08 mandate append-only immutability triggers (`prevent_ledger_mutation`, `verify_journal_balanced_at_commit`) and hash-chained audit logs (`computeAuditChainHash`).
  - **Conflict**: Storing raw PII (full name, email, street address) directly inside `journal_postings` or `audit_logs.payload_json` makes GDPR erasure impossible without breaking the cryptographic hash chain or violating ledger immutability!
  - **Mandatory Pattern**: Store only pseudonymous `user_id` / `account_id` UUIDs in immutable ledger and audit tables, and store mutable/erasable PII in a separate `user_pii_profiles` table encrypted with a per-user key (`encryptEnvelopeAes256Gcm` in Module 16, crypto-shredding on erasure).

### 5.3 Production Deployment Risk Report & Explicit Unresolved / External-Dependency Findings
In accordance with the ARGON — DEVILSCANNER operating rules, the following items cannot be verified in-process without external infrastructure daemons and remain **Explicit Operational / Infrastructure Dependencies**:
1. **`UNRESOLVED-INFRA-01` (Live PostgreSQL 16 Daemon & Role/Extension Provisioning)**:
   - While `verifyDatabaseRoleRlsEnforcement()`, `withTenantTransaction()`, and the SQL DDL for `pgcrypto`, `security.verify_active_tenant_context()`, `security.verify_active_user_context()`, `FORCE ROW LEVEL SECURITY`, and `verify_journal_balanced_at_commit()` are completely implemented in Modules 01, 07, 11, and 13, this container does not run a live PostgreSQL server daemon. Those SQL scripts must be applied and integration-tested against a live PostgreSQL 16 instance in CI/staging.
2. **`UNRESOLVED-INFRA-02` (Binary Media Re-Encoding Libraries & Live ClamAV `clamd` Daemon)**:
   - `StreamingMultiStorageOrchestrator` enforces the `MandatoryCdrSanitizerInstance` (`performsFullFormatReconstruction: true`), full-stream EOF verification, and JPEG/PNG/WebP header dimension parsing in TypeScript, but production deployments require a live `clamd` daemon (`zINSTREAM`) and native `sharp`/`libvips` + `qpdf`/`pdfcpu` workers to reconstruct full image/PDF streams at runtime.
3. **`UNRESOLVED-INFRA-03` (VPC Egress Firewall & Cloud Metadata IMDSv2 Hop Limit)**:
   - Application-layer SSRF checks (`executePinnedSafeHttpsRequest`) do not stop native C++ addons or child processes (`curl`, `ffmpeg`) from reaching cloud metadata (`169.254.169.254`). Production deployments MUST enforce AWS IMDSv2 (`HttpPutResponseHopLimit = 1`) / GCP Metadata Concealment and VPC egress firewall rules blocking RFC 1918 and link-local destinations.
4. **`UNRESOLVED-INFRA-04` (Multi-Pod Distributed Coordination for Local Single-Flight & Circuit Breakers)**:
   - `inFlightLocalPromises` (Module 03 single-flight coalescing) and `CircuitBreaker` state (Module 04) are per-Node.js-process memory structures; cross-pod coordination requires Redis-backed distributed leases or service-mesh circuit breaking.
